## What changed

- **F1 account menu** (`App.tsx`): the lane and role list is gone for every account. The trigger and the menu header show `me.name` (the tester keeps the "Test view ·" prefix and "test view," in the aria-label). Tester switch, "Suggest an improvement", "Platform questionnaire" and "Sign out" are unchanged.
- **F2 period on the request** (`schemas.py`, `service.py`): `BriefingQuery.week_end` (optional, a Monday, not before `week_start`; one validator covers both Mondays). `normalize_question` writes `Weeks of A to B in <Territory>: ...` when `week_end > week_start`, else `Week of A in ...`. `window.parse` already reads that text (tested, `window.py` untouched). `service._check_scope` checks `week_end` is in the release and gives the comparison the whole period (`period_weeks`), so "same weeks last year" is judged week by week. `BriefingResult.week_end` carries the period into the stored brief (scripted, agent worker result); the triage plan dict gets `week_end` too. The plan id and the agent job round trip carry the period through the question text and `query.model_dump`.
- **F3 form** (`App.tsx`, `ComparisonPicker.tsx`, new `BriefingScope.tsx`): First week and Last week selects (Last week lists only weeks from First week on; with one week chosen, changing First week moves Last week with it); "Compare with the previous [N] weeks" number field, 1 to 13, default 4, always sends `{"kind":"previous","weeks":N}` (not `null`); "Other comparison" (a `<details>`) holds last year and custom. `comparisonError(value, periodWeeks, releaseWeeks)` and `periodError` validate in code; errors show beside the field and disable "Generate briefing". The Promotion review box still disables the period and sends no comparison. The question box is now always shown (it was agent and promotion only), because "Read my question" lives with it.
- **F4 route** (`app.py`, `service.py`, new `briefing_agent/reader.py`, `prompts/scope_reader.md`): `POST /api/briefing/scope` `{question, brand_id}` returns `{question, week_start, week_end, territory_id|null, comparison_weeks, promotion_review, notes, read_by, model}`. Analysts only (`run` action; leaders, other roles and the tester viewing as leadership get 403; brand access checked). A model is used only when `PHARMAGENTICS_AGENT_MODEL` starts with `anthropic:` and `ANTHROPIC_API_KEY` is set (`service.scope_model`, separate from the in-app worker flag). The model makes one `set_scope` tool call (period as calendar dates, territory, comparison weeks, promotion flag; it writes no prose). `service.validate_scope` checks every field: dates parse and order, weeks are Mondays inside the release, known territory, comparison a real int 1 to 13 whose weeks all exist before the first week, promotion a bool (BXA only). Any exception or failed check falls back to `window.parse` (`rules_scope`), `read_by="rules"`. The rules read the whole question (colons neutralised), shorten a 4-week comparison that would reach before the release (with a note), and set the promotion flag from `parse`. `territory_id` is null when none is named, so the form keeps its territory.
- **F5 UI** (`BriefingScope.tsx`): "Read my question" calls the route, re-checks the proposal in the browser (`scopeToForm`), and fills territory, weeks, promotion box and comparison. It shows "Read by Haiku", "Read by the model" or "Read by rules" plus the notes. A proposal that fails the browser check is refused with its reason and the form keeps its last values. Nothing runs until the analyst presses "Generate briefing".
- **F6 tests**: new `tests/test_briefing_scope.py` (26 tests: validation, normalisation and `window.parse` round trip, scope check on a period, rules reading, model path with a stub, ten invalid proposals falling back, model failure, wrong brand, analysts only incl. tester switch, brand access, `scope_model` env rules, no eval or agent file references the reader, reader tool call with a stubbed agent); three new tests in `tests/test_briefing_api.py`; `BriefingScope.tsx` added to the allow-list in `tests/test_frontend_scope.py`. Every test stubs the model and `service.scope_model`, so a real `.env` never reaches a real model.
