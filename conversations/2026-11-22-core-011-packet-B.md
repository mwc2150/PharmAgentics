# core-011 packet B: run insights (2026-11-22)

## What changed
- `eval/harness/insights.py`: reads MLflow sqlite store(s) with `mode=ro`. Parent runs (no `mlflow.parentRunId` tag), their child traces, scores from `assessments` (JSON numbers and booleans only; `expectation` rows and run counters are left out of the lists). Each trace question maps to a golden case by the text after the last colon, falling back to the first 60 characters; ambiguous or unmatched traces are counted as unmapped.
- Lists: stuck (a scorer at 0 in every listed run), fallen (latest below the previous run of the same system by more than 0.001, same golden only), engine comparison (latest scripted vs latest agent or lowcode, per lane), rerun spread (per-run std above 0.1), golden-version breaks (adjacent runs with different `golden_version`, marked not comparable).
- `eval/__main__.py`: one `insights` subcommand (`--store` repeatable, `--system`, `--last` default 5, `--out` default `eval/mlflow/insights/`).
- `eval/tests/test_insights.py`: four tests on a SQLite fixture built in the test (stuck, fallen, engine, spread, golden break, system filter, markdown, read-only open).
- Output: `insights.md` (short tables, story labels next to case IDs) and `insights.json` (per-system matrix of means and stds, plus the lists).
- Operational counters (`seconds`, `llm_calls`, `tool_calls`, `hit_cap`, `needed_revision`) stay in the matrix but are left out of the lists, since they would show as stuck on the scripted baseline.

## How to run
- `uv run python -m eval insights` (default store `eval/mlflow/mlflow.db` in the tree you run from)
- `uv run python -m eval insights --store <path> --system briefing_scripted --last 3 --out <dir>`
- `uv run pytest -q eval/tests/test_insights.py`
