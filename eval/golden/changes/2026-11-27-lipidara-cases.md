# BXC-P1-Q1 to BXC-P4-Q6: 24 Lipidara Briefing cases added

- Date: 2026-11-27
- Cases: BXC-P1-Q1 to BXC-P4-Q6 (C-033 to C-056), new files `eval/golden/briefing/BXC-*.yaml`; no existing case changed
- Source: docs/planning/user-stories-lipidara.md (a draft for Michael to copy into the master Google Doc)

One case per Briefing persona question for Lipidara (BXC), the way the Cardiovela (BXA) set was built: stories first, each anchored on a real week or event in the release, then the case with `definition`, `facts` (number plus the SQL that recomputes it), `findings`, `must_not_say` and `eval_items`. All four personas are covered. Every case is `brand: BXC`, `split: dev`, `status: draft`; every fact, finding and `must_say` is `reviewed: false` until Michael reviews it. 59 facts are `must`, 161 are `context`, 18 findings. `uv run python -m eval check` recomputes all 401 facts from the data and passes.

**Assumptions first.** Each case states every `definition` field, and each fact's SQL makes its window explicit: the question's weeks, the stated comparison weeks (previous 4 weeks, previous 1 week, the pre-launch weeks 2026-02-02 to 2026-02-23, or the summer 2025-06-02 to 2025-07-28), like for like on the territories whose feed passes in every week compared (the BXA SQL pattern), and holiday weeks left out of a period. Findings name their measure when it is not BXC TRx (`nbrx`, `competitor_share`, `bxa_share`).

**Anchors.** Lipidara has few events of its own, so the set leans on what the release holds for it: Metacora's launch (P2-Q2, P3-Q1, P3-Q3, P3-Q4, P4-Q2, P4-Q6, with P1-Q5 and P1-Q6 for a single week), the three feed artifacts (P1-Q1, P1-Q2, P2-Q1, P2-Q5, P3-Q6), the December holiday weeks (P3-Q2), one Mid-Atlantic Medicare Part D plan that Lipidara gained on while Cardiovela's access was restricted (P1-Q4, P2-Q4, P3-Q5, P4-Q3, P4-Q4, P4-Q5), a South Central gap with no driver (P2-Q3), a quiet week (P1-Q3) and a single-week rep-call spike (P4-Q1). Where the right answer is "nothing material" or "not supported" the case says so and carries no finding (P1-Q3, P2-Q6, P3-Q6, P4-Q1, P4-Q3, P4-Q5, P4-Q6).

**Decisions to review.**
- **Competitor access context.** P1-Q4, P2-Q4, P3-Q5, P4-Q4 and P4-Q5 cite Cardiovela's tier change on the Mid-Atlantic plan, because it is the only access event that touches Lipidara's numbers. core-010 permits named aggregate competitor TRx and shares in an authorized workspace; it does not say whether a competitor's formulary position is permitted context. If it is not, these five cases need their cause reworded. Their plan-level facts carry `needs: plan_cut`.
- **Driver for the plan story.** The plan's Lipidara rise is tagged `competitor` (Lipidara's own access, promotion, supply and feeds are unchanged). The evidence is modest (21.1% against 11.5% for the territory's other plans) and did not reverse when Cardiovela's tier returned on 2025-11-01, so P4-Q4 leaves the excess unexplained and P4-Q5 says Low confidence.
- **Share measure name.** `bxa_share` in a finding means the selected brand's own share (the engine's `stages.py` fills it with `p.brand_id`), so the Lipidara share findings use it as written.
- **Categories** follow the BXA draft mapping, except P1-Q5, P4-Q4 and P4-Q5 (`real_event`: Lipidara has one live story, not a compound week) and P4-Q1 (`null_week`: the spike week has no effect).
- **P3-Q2 must-not-say** is judge-only (semantic): `"BXC fell 20%"` with no calendar label. The correct brief states that drop and labels it a calendar effect, so a phrase match would fail the right answer. (The first BXC run, e7a8aa59, scored `must_not_say` 0.958 on the phrase form; this version scores 1.000.)
- **Not changed on purpose:** the BXA cases, `eval/golden/CHANGELOG.md`, the specs and the engine.

**Harness** (eval only; nothing in `src/` or `agents/` imports it): `brand` on a case (default BXA; `load_cases` and `golden_fingerprint` default to BXA, so every older caller reads the cases it always did), `eval run --brand BXA|BXC|all`, a `brands` tuple on every system (only `reference` and `briefing_scripted` support BXC; an unsupported case is listed on the run as `skipped_cases` with a `cases_skipped` metric and never run, scored or counted as a run error), a BXC or mixed run logged as its own system row (`briefing_scripted@BXC`) with per-brand pooled metrics (`_bxa`, `_bxc`) in a mixed run, `eval import-stories --brand BXC`, and `eval check` over every brand. A BXA-only run logs exactly what it did before: run `720d1410` (before) and `56261039` (after) have identical metrics and the same golden version, and `eval gate` exits 0.
